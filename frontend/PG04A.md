# Playground inventory operations

The dedicated receiver uses the site-wide `playground-identities` Netlify Blobs store. Its receiver code permits access only from the published production deploy. Automatic builds on this dedicated site are stopped because Netlify shares site-wide stores across deploy contexts; deploy reviewed code manually. Each key is a resource ID; conditional creation rejects changes to an existing identity. The readiness endpoint requires the shared server secret and returns only the application and resource IDs and readiness, never the identity.

The existing PG03B batch has been copied to the current user's restricted `.codex/trycove-pg04a-recovery/existing-batch` directory. It contains the provisioner, owner and delegate keys. Its two recipient keys per scenario were not saved by the old provisioning script and are unavailable. Do not delete the original or recovery copy.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File ./pg04a-import-existing.ps1` from this directory to import that batch. The script prompts securely for a Netlify personal access token, verifies the dedicated site, and never puts the token or identities in command arguments. Repeating the import is safe if existing records are identical; conflicting records stop the import. The token needs access to the dedicated site. Import does not fund or create a Pocket.

For new inventory, set `PG04A_QUANTITY` (1–20) and optionally `PG04A_PAYMENT_CKB` (61–122), then run `npx tsx pg03b-prepare-batch.ts initialize`. Securely retain the resulting directory. Fund its provisioner only within an authorized budget, set `PG03B_SCENARIO_DIR` to that directory and `PG04A_FUNDING_BUDGET_CKB` to the maximum total provisioner spend, then run `npx tsx pg03b-prepare-batch.ts prepare`. Preparation checks the Pudge genesis and saves private signed intents before broadcasting. A retry reconciles the original transaction hashes; it never constructs a replacement for an existing intent. Concurrent preparation is locked and stale locks expire after 30 seconds. The browser transaction utilities run directly without a frontend server.

Set `NETLIFY_AUTH_TOKEN`, `NETLIFY_SITE_ID` and `PG03B_SCENARIO_DIR` in the local process environment and run `node pg04a-import-inventory.mjs` to import another completed batch. The script verifies the site's identity, performs strong reads and conditional writes, and outputs only resource IDs. Keep tokens and keys out of arguments and logs. Register public resource metadata with Trycove only after importing.
