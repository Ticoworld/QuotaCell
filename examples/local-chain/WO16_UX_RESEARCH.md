# WO16 research and interaction audit

Research performed on the linked public pages, not with QuotaCell users: [NN/g progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) recommends deferring advanced features; [NN/g cognitive load](https://www.nngroup.com/articles/minimize-cognitive-load/) recommends reducing memory and translation demands. [Baymard's form-field research](https://baymard.com/research-articles/checkout-flow-average-form-fields) motivates collecting only necessary fields; its checkout findings are an analogy, not a measured result for Pocket creation. [GOV.UK check answers](https://design-system.service.gov.uk/patterns/check-answers/) supports an editable summary before submission. [W3C WCAG error identification](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) calls for text identifying input errors. The [Safe Wallet](https://safe.global/wallet) and [Ramp budgets](https://ramp.com/budgets) public pages illustrate transaction control and budget context; these were public descriptions, not hands-on account tests. [Nervos CCC documentation](https://docs.nervos.org/docs/integrate-wallets/ccc-wallet) describes wallet connection and signer use. [ckb-session-kit](https://github.com/luongthanhtung03/ckb-session-kit) describes scoped session authority, which is a different model and is not added to QuotaCell. These are reference findings, not independent usability testing.

The existing first screen mixes wallet selection, raw policy JSON, technical identifiers, account setup, both delegates, spending, owner controls and history. It forces new users to translate limits into contract inputs, and its transaction review presents technical locks. The existing backend already exposes state, separate prepare/submit endpoints and wallet signing; it does not supply a verified public Pocket until one exists.

Two directions were considered: (1) an operations console with all controls visible and (2) a Pocket-centered journey showing the shared allowance and current task first, with participant setup and transaction details disclosed when needed. Direction 2 better supports the distinct owner and delegate tasks and reduces irrelevant choices. A central connected-cell visualization can explain that two independent delegates consume one shared allowance while balance and authority remain separate. Preserve a technical inspector and the original interface during migration; never substitute example balances for chain state.

The React dashboard is now the main summary surface and reads live server state. Its wallet, registration, term entry, payment, owner control and transaction review actions run in the existing Working Pocket inside an embedded workspace; the standalone HTML URL remains available as fallback. This avoids a second transaction-signing implementation. Chromium rendered the React empty and onboarding states and verified the proxied live API. A fresh run reached those states but stopped before active/closed React captures, so those React states and their mobile layouts remain unverified. The existing HTML owner/delegate lifecycle has active and closed screenshots. There has been no independent user study, accessibility audit or public-Pocket lifecycle qualification.

The fallback now accepts editable allowance fields, offers public profile exchange and shows a shared allowance indicator alongside separate participant limits. It still exposes advanced JSON and technical controls and does not implement the complete proposed guided review. A fresh isolated Chromium and CKB-node lifecycle passed with additional funding, both delegate revocations, multi-fund recovery, late sweep and restart. Both post-revocation refusals in that run were application-level checks. The React migration remains incomplete: the draft overview is not connected to wallet actions and was not qualified as a replacement. `npm install --ignore-scripts --no-audit --no-fund --fetch-timeout=15000 --fetch-retries=0` stalled without output and was interrupted; `npm run build` then failed because `tsc` was unavailable. The draft has not been published as a product interface.
