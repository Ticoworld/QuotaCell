# Working Pocket implementation map

> Historical WO16 snapshot. WO17 replaced the embedded legacy workspace with native React wallet and transaction flows. See [WO17_IMPLEMENTATION_MAP.md](WO17_IMPLEMENTATION_MAP.md) for the current architecture and [WO17_EVIDENCE.md](WO17_EVIDENCE.md) for the tested scope.

The React/Vite dashboard reads `GET /api/state` from the existing Working Pocket server. It presents live protected funds separately from shared lifetime authority, shows each delegate's remaining and per-payment limits, labels unsupported Cells as unrecovered, and displays transaction states with Pudge explorer links only in Pudge mode. Owner and delegate actions open the existing wallet workspace in a same-origin iframe; wallet identity is reported back to React so the action prompt follows the connected role. The original HTML page remains directly available at the backend root and at `/legacy` through Vite.

Vite proxies `/api`, `/wallet.js` and `/legacy` to the backend. Its API proxy supplies the backend's exact local origin because that server checks the request origin. `QUOTACELL_BACKEND_URL` can point Vite at another local backend port for isolated tests. `POST /api/ckb` proxies a restricted set of read-only RPC methods. `/api/external/genesis`, `/prepare` and `/owner` build unsigned intents; `/submit` verifies the returned external-wallet signature and intent, checks live inputs, journals and submits once when public submission is explicitly enabled. `/api/reconcile` observes known transactions without resending. Development-only `/api/pay` and `/api/owner` use local disposable signers and are forbidden on Pudge.

`pocket_genesis.mjs` constructs QCN4 policy state and Type ID. `pocket_payment.ts` checks shared and personal counters and creates payments. `pocket_input.mjs` parses exact decimal amounts and supported recipient addresses; `pocket_signing.mjs` validates the wallet signature and transaction. Discovery uses the isolated scan or independently validated Pudge indexer results. `policy/c/allowance_native_v2.c` is the existing contract, not changed by this interface work.

The server's local descriptor and journal hold public identities and signed transactions, not wallet private keys. Public restart discovery currently needs that descriptor, and no complete public Pocket lifecycle has been demonstrated. Unsupported data-bearing protected Cells are reported separately and their own recovery is not implemented. Transaction reviews show the backend's calculated fee and recipient/output details before wallet approval. The owner-controlled deployed Q Cell must not be consumed.
